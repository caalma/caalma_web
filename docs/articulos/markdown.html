Los artículos de esta web se escriben en Markdown, con algunas extensiones y un par de agregados propios. Esta guía recorre todo lo que se puede usar. Cada ejemplo muestra primero el código fuente y después cómo se ve, así que sirve también como hoja de referencia.

Cómo se arma un artículo#

Un artículo son dos archivos:

  1. Un YAML en base/datos/paginas/ con los datos de la página.
  2. Un Markdown en base/datos/articulos/ con el texto (o el texto escrito dentro del propio YAML, con md: |).

Además de esos campos, la página acepta portada (una imagen bajo el título), portada_alt, color (el acento de la página), toc_nivel (qué títulos entran en el índice lateral, por defecto '2-3'), paneles (paneles sueltos disponibles en la página) e indexar: false (para sacarla del sitemap.xml).

El texto pasa por tres etapas, en este orden:

  1. Plantillas Jinja: se reemplazan cosas como {{ cfg.base }}.
  2. Markdown: se convierte a HTML.
  3. Resaltado: los bloques de código reciben colores y un botón para copiar.

El título de la página

El # título principal sale del campo titulo del YAML. Dentro del texto se empieza en el nivel 2 (##), que es el primero que entra en el índice lateral.

Texto#

Párrafos y saltos de línea#

Un párrafo es un bloque de texto separado de otro por una línea en blanco. Un salto de línea simple dentro de un párrafo no corta la línea: para forzarlo hay que terminar la línea con dos espacios.

Énfasis y código en línea#

cursiva o cursiva, negrita o negrita, ambas. Un fragmento de código dentro de la frase. Para escribir un asterisco literal: *así*.

El carácter \ escapa cualquier signo de Markdown: `* _ # [ ] ( ) { } ! | ``.

Formatos que se escriben con HTML#

Markdown no tiene sintaxis para todo. Lo que falta se escribe con las etiquetas HTML, que funcionan dentro del texto y ya tienen estilo en esta web:

resaltado, tachado, Ctrl+C, H2O, x2, texto chico, abbr.

Las entidades HTML (&copy;, &amp;, &lt;, &nbsp;) también se interpretan: © & <.

Títulos#

Dos sintaxis#

Cada título recibe un identificador automático a partir de su texto (en minúsculas, sin tildes y con guiones): «Énfasis y código en línea» pasa a ser enfasis-y-codigo-en-linea. Con él se puede enlazar a una sección y, en esta web, se genera el índice lateral, el enlace # que aparece al apoyar el cursor sobre el título y el salto con la palabra IR del lenguaje pila-web.

Identificador y clase propios#

Con la extensión de atributos se puede fijar el id o agregar clases:

Usar siempre {: …}, con dos puntos

La forma corta {#mi-id} es válida en Markdown, pero acá no sirve: Jinja interpreta {# como el comienzo de un comentario y se traga el resto del texto. La forma {: #mi-id } no tiene ese problema.

Índice dentro del texto#

El índice lateral se genera solo. Si además se quiere un índice en un punto del texto, se escribe [TOC] en una línea aparte. Se recomienda no usarlo en artículos, donde ya hay uno.

Enlaces#

Los enlaces internos al sitio se escriben con {{ cfg.base }}, que vale / (o la carpeta del proyecto si el sitio no está en la raíz): [inicio]({{ cfg.base }}) da inicio.

Abrir en otra pestaña#

Con atributos se indica el destino. Una pestaña nueva es _blank; un nombre propio reutiliza siempre la misma pestaña:

Pestaña nueva · Pestaña con nombre

Direcciones sueltas

Una dirección escrita sin más (https://ejemplo.com) no se convierte en enlace. Hay que encerrarla entre < y >, o usar la sintaxis completa.

Imágenes#

Sintaxis básica#

La imagen se escribe como un enlace precedido de !. El texto entre corchetes es el texto alternativo (lo leen los lectores de pantalla y se ve si la imagen no carga).

Las imágenes nunca desbordan la pantalla: se achican para entrar en el ancho de la columna y no pasan del 70% del alto de la ventana, siempre conservando la proporción.

Flotar junto al texto#

Las clases izq y der hacen que la imagen quede a un lado y el texto la rodee. En pantallas angostas vuelven a ser imágenes centradas.

Este párrafo rodea a la imagen que flota a la derecha. El atributo width fija un ancho en píxeles; sin él, la imagen ocupa hasta el 40% de la columna. Lo mismo vale para .izq. El texto sigue fluyendo alrededor hasta que la imagen termina.

Para una imagen debajo del título de la página, sin escribirla en el texto, está el campo portada del YAML.

Código#

En bloques#

Un bloque se encierra entre tres acentos graves (o tres tildes ~~~) y se indica el lenguaje a continuación. El resaltado lo hace Pygments, que reconoce cientos de lenguajes (python, javascript, html, css, yaml, json, bash, sql, c, rust, diff, markdown…). Además, esta web agrega pila-web, el lenguaje propio del sitio.

Cada bloque con lenguaje muestra su nombre arriba y un botón copiar. Sin lenguaje, el código se muestra sin colores:

Tablas#

La primera fila son los encabezados; los dos puntos de la segunda fila fijan la alineación de cada columna.

IzquierdaCentroDerecha
ab1,5

Las celdas aceptan formato en línea (énfasis, código, enlaces, imágenes pequeñas). No hay celdas combinadas ni varias líneas dentro de una celda. Si una tabla es más ancha que la pantalla, desliza horizontalmente sin ensanchar la página.

Avisos#

Los avisos destacan un párrafo. Se escriben con !!!, el tipo, un título opcional entre comillas y el contenido sangrado con cuatro espacios:

Nota

Información complementaria. Es el tipo por defecto.

Consejo

Una sugerencia útil (tip, también hint y success).

Atención

Algo que conviene tener presente (warning, también caution y attention).

Peligro

Algo que puede romper cosas (danger, también error).

Un aviso puede ir sin título (con comillas vacías) y también puede contener otros avisos y bloques de código:

HTML dentro de Markdown#

Se puede escribir HTML en cualquier parte. En un bloque HTML (div, section, figure, details…) Markdown no procesa el interior, salvo que la etiqueta lleve el atributo markdown="1":

Los comentarios HTML (<!-- así -->) llegan al HTML, pero se eliminan al publicar si está activado optimizar_codigo.

Con HTML también se pueden incluir elementos que reaccionan mediante el lenguaje pila-web, como botones o campos de texto. Hay un artículo dedicado a eso: pila-web, el lenguaje de la página.

Plantillas Jinja#

Antes de convertirse en Markdown, el texto pasa por Jinja. Sirve para insertar valores de la configuración:

Se escribeVale
{{ cfg.base }}/
{{ cfg.urls.sitio }}https://caalma.net.ar
{{ cfg.urls.repositorio }}https://github.com/caalma/caalma_web
{{ cfg.actualizacion }}2026-11-27 11:17:51

Lo que no está soportado#

Algunas sintaxis de otras variantes de Markdown no funcionan acá. Se ven como texto literal, así que conviene saberlo:

No funcionaAlternativa
~~tachado~~<del>tachado</del>
- [x] tarea (listas de tareas)una lista común con símbolos: ✓ y ○
https://ejemplo.com suelto<https://ejemplo.com>
Salto de línea con \ al finaldos espacios al final de la línea
$x^2$ (fórmulas), :smile: (emojis)escribir x<sup>2</sup>, o el carácter Unicode: 🙂
{#id} en un título{: #id }
Numeración o resalte de líneas de códigobloque diff, o explicar en el texto
